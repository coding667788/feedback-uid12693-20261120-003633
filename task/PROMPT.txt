请实现一个离线的应用执行控制服务。模拟企业安全代理在启动软件前向本地白名单服务申请准入，只把判定结果写入合成启动清单，不运行被申请的程序。请求绑定组织、设备代数、应用内容 SHA-256、签发者、经过当前签发链验证的摘要及完整入口路径。设备策略由组织基线和设备组规则组成，分为摘要允许、签发者与路径段联合允许、明确拒绝。拒绝覆盖所有允许，缺少有效授权默认拒绝。签发者凭据轮换、吊销与设备转组会改变代数。允许规则可为设备组临时放宽但需两位不同审批者，且不能放宽任何明确拒绝。

一个软件启动可包含主程序和至多 25 个合成依赖，全部需通过同代策略；所有部分都允许才生成一条持久准入记录。准备阶段可读取一次快照作为提示，SQLite 提交事务内必须重新核对所有受影响的代数、规则有效期和当前吊销。幂等回执固定当时使用的政策版本和命中规则。同一摘要移动到不同入口或签发者换钥后的新请求必须重判。

测试用两个独立进程固定“旧策略预检后设备转组”“一项依赖许可被吊销”“先准入后策略撤回”的相反顺序，真实终止自建工人于清单写入未提交及提交完成后，重开数据库证明不会留下部分准入和重复行。另用至少 30 条合成策略提供独立决策表，核对同名路径段、临时权限到期及远端签发者模拟状态变化。

在 Windows 原生 Python 3.12、标准库和 CPU 环境下实现，全部输入自行合成，离线测试。交付源码、README、可重放 cases.json 和自动化测试。提供 python -m solution --input cases.json --output result.json 与 python -m unittest discover -s tests -v。测试须断言具体结果，README 写明规则、输入输出、错误码和实测结果。
